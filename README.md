# 🏦 Banking API

### ⚡ Production-Style Banking Backend

> A backend system designed around financial transactions, concurrency, consistency, security, and reliable state management.

## 🚀 Engineering Features

### 🔴 Advanced — Core Engineering Challenges

#### 1. Concurrent Transaction Processing

* PostgreSQL row-level locking with `SELECT ... FOR UPDATE`
* Handles concurrent fund transfers safely
* Prevents race conditions and double-spending
* Locks sender/receiver account rows during transfers

#### 2. ACID Financial Transactions

* Atomic multi-step fund transfers
* Explicit transaction boundaries
* Commit / rollback handling
* Maintains consistency across account, transaction, and ledger updates

#### 3. Transactional Ledger

* Records debit and credit operations
* Links ledger entries to transactions and accounts
* Maintains an auditable financial history
* Rolls back together with the transaction when failures occur

#### 4. Idempotent Transactions

* Redis-backed idempotency keys
* Prevents duplicate financial operations
* Stores completed transaction responses with TTL
* Retry requests return the previously processed result

---

### 🟠 Intermediate — Reliability & Security

#### 5. Redis Sliding-Window Rate Limiting

* Redis-based request tracking
* Sliding-window rate limiting
* Uses `WATCH / MULTI / EXEC` for atomic updates
* Protects sensitive transaction endpoints

#### 6. Authentication & Session Management

* JWT authentication
* Access + refresh tokens
* Redis-backed sessions
* Protected endpoints
* Token validation and expiration

#### 7. Failure-Safe Error Handling

* Explicit rollback on failed operations
* Handles expected application errors separately
* Prevents partial financial state
* Safe failure responses for unexpected errors

#### 8. Audit Trail

* Records important financial actions
* Associates actions with users and transactions
* Stores action descriptions and context
* Provides traceability for financial operations

---

### 🟡 Database & Backend Engineering

#### 9. PostgreSQL + SQLAlchemy

* Relational data modeling
* Foreign-key relationships
* Unique constraints
* SQLAlchemy ORM
* Database-level consistency

#### 10. Schema Versioning

* Alembic migrations
* Version-controlled database schema
* Reproducible database changes

#### 11. Layered Backend Architecture

```text
             API / Controllers
                     │
                     ▼
                  Services
                     │
                     ▼
                Repositories
                     │
                     ▼
                 PostgreSQL
```

* Controllers handle HTTP concerns
* Services contain business logic
* Repositories handle database operations
* Transaction boundaries controlled by the service layer

#### 12. Transaction History

* Transaction history APIs
* Pagination
* Structured response schemas
* Repository-based querying

#### 14. API Documentation
